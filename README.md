# BNOC 업무 관리

통신 지원 요청·작업 진행과 부서 운영 현황을 관리하는 PC용 웹 서비스다. React 화면·Spring Boot 서버·MySQL 저장소와 요구사항부터 검증까지의 개발 문서를 함께 제공한다. 실제 공군 SSO·GPS·CPCON 연결은 후속 범위이며 현재 별도 모의 제공자를 사용한다.

**설계 0.7의 백엔드·부대 운영 화면을 구현하고 실제 실행을 검증했다.** 2026-10-13 사용자가 설계대로 구현과 접속 주소 반환을 승인했다. 현재 실행 방법은 아래를 따른다. 실제 공군 연동과 이식성 고도화는 후속 범위다.

**현재 중간 목표는 PC 전용 완성도 개선이다.** 사용자가 모바일 범위를 폐기하고 개선 구현을 승인했다. [범위·합격 기준·실행 기록](docs/작업기록.md#desktop-quality-20261014)을 따른다. 현재 모바일 지원은 없다. 과거 실행 증거는 당시 이력이다.

## 설계 검토

[아키텍처 설계 웹](아키텍처설계.html)은 **백엔드·부대 운영 설계 0.7**이다. 원래 모듈 카드·함수·연결 탐색을 유지하면서 35개 기능 명세를 38개 책임 단위·70개 호출 관계에 연결했다. BNOC 사후 분류·작업반 담당 인원·부서 명부·과거 현황·공지 공동 수정과 공개 CPCON 등급 근거를 반영했다. 설계 웹은 제품 화면과 구별하며 원본 복구본은 Git `fed2b10`에 보존했다.

## 현재 제품

React 화면과 API를 하나의 Spring Boot JAR에서 제공한다. 요청·작업·이력·알림·명부·병력·야간 근무·공지는 MySQL에 저장하며 첨부 내용은 비공개 파일 경로에 보관한다. 서버 세션과 현재 권한을 검사한다. 사용자 화면은 역할명으로 로그인하며 명부는 비어 있는 상태에서 부서 담당자가 입력한다. 자체 회원가입·가짜 이름·합성 계급·임시 단계는 사용하지 않는다.

현재 공개 시연 주소: **[BNOC 업무·부대 운영](https://vessel-cups-electric-spa.trycloudflare.com)**. 새 JVM/DB 제품이며 공개 HTTPS 로그인·업무 저장·첨부·재시작 보존을 검증했다. 컴퓨터·MySQL·서버·터널이 실행 중일 때 이용하는 임시 주소다. 상시 호스팅 완료는 아니다. 현재 주소와 실행 상태는 `npm run server:public-status`로 확인한다.

2026-10-14 로그인·상단·인증 창·GPS/CPCON의 구현 설명을 제거하고 같은 공개 주소에 반영했다. 최신 [실행 결과](docs/개발진행.md)는 이번 표시 검사와 이전 전체 업무 검증을 구별한다.

`a10bb49`의 [기존 공개 정적 데모](https://bnoc-operations.allsoft1004.chatgpt.site)는 과거 배포본이다. 이번 JVM/DB 제품을 그 주소에 배포하지 않았다. 로컬 실행의 기본 주소는 `http://127.0.0.1:8081`이다.

## 실행과 검증

Node.js 22 이상·Java 17·Gradle 9.3.0·MySQL 8.4가 필요하다. 실행 도구와 의존성 바이너리는 이 공개 스냅샷에 포함하지 않는다. 각자의 환경에 설치한다. 실행기는 기본으로 `.local/dependencies/gradle-9.3.0`과 `.local/dependencies/mysql-8.4.11-macos15-arm64`를 사용한다. 다른 설치 경로는 `BNOC_GRADLE` 실행 파일·`BNOC_MYSQL_HOME` 설치 디렉터리로 지정한다.

```bash
npm install
npm --prefix frontend install
npm run server:build
npm run server:start
npm run server:status
```

제품은 8081, 별도 모의 제공자는 8082, 이 프로젝트의 MySQL은 3307에서 실행한다. 시작 실행기가 자기 서비스를 백그라운드로 유지한다. 새로고침과 업무 서버 재시작이 DB·첨부를 초기화하지 않는다. 비밀·DB·첨부·프로세스 기록은 Git에서 제외한 `.local/bnoc-runtime/`에 보관하며 기존 3306 DB를 사용하지 않는다. 종료는 `npm run server:stop`이다.

공개 시연 실행기는 `npm run server:public-start`다. 공식 [cloudflared](https://developers.cloudflare.com/tunnel/downloads/)를 `.local/dependencies/cloudflared/cloudflared`에 준비하고 위 도구·JAR을 사용한다. 별도 8085 서버·8086 모의 제공자·`bnoc_public_demo` DB·`.local/bnoc-public/attachments`를 사용하며 기존 제품·검증 DB를 복제하지 않는다. 브라우저 로그인도 공개 서비스의 `/identity`를 사용한다. MySQL·컴퓨터·공개 서버·터널이 실행 중이어야 접속하며 터널을 새로 시작하면 주소가 바뀐다. 상태/현재 URL은 `npm run server:public-status`, 저장을 유지한 서버 재시작은 `npm run server:public-restart`, 공개 서비스만 종료하려면 `npm run server:public-stop`이다. 이는 상시 호스팅이 아니다.

로그인에서 역할을 선택해 요청자·BNOC·작업반·부서 담당자·권한 관리자 흐름을 확인한다. 역할 변경은 로그아웃 후 다시 로그인한다. 추가 부서는 `BNOC_DEPARTMENTS`의 쉼표 구분 목록으로 서버 시작 시 등록하고 권한 관리 화면에서 부서 담당자를 지정한다.

검사는 별도 8083 서버·`bnoc_verify` DB·첨부 경로를 사용한다. HTTP·브라우저·저장 검사는 모의 제공자의 상태를 바꾸므로 순서대로 실행한다.

```bash
npm run server:verify-start
npm test
npm run test:provider
npm run test:server
npm run test:e2e
npm run test:server-storage
npm run test:server-sensitivity
```

과거 데모의 단위 검사·업무 흐름 원본은 보존한다. 새 제품 검사는 API 사용·DB 보존을 확인하므로 새로고침 초기화를 기대하는 옛 브라우저 검사를 현재 제품의 합격 기준으로 사용하지 않는다. 실행 결과는 [개발 진행](docs/개발진행.md)과 [업무 검증 기록](docs/업무검증기록.md)에 연결한다. 2026-10-14 최종 JAR은 서버 35/35·화면 단위 48/48·모의 제공자 3/3·HTTP 26/26·전체 UI 54/54를 통과했다. 공개 HTTPS 독립 검증 10/10·두 브라우저/세 너비·공개 서버 재시작/첨부 보존도 확인했다. 2026-10-13의 실제 DB 동시 저장·롤백·재시작/첨부 보존과 당시 8081 검사 증거는 수행판을 구분해 보존한다.

설계 웹은 `아키텍처설계.html`을 브라우저에서 직접 연다. 원본의 Google Fonts 참조는 유지했다. 외부 폰트를 불러오지 못해도 기본 글꼴로 탐색할 수 있다.

설계 검토에 사용한 [로컬 주소](http://127.0.0.1:4175/%EC%95%84%ED%82%A4%ED%85%8D%EC%B2%98%EC%84%A4%EA%B3%84.html)는 제품 서버와 별개다. 설계 0.7의 정적·브라우저 6조합·격리 오류 9건 검증 결과는 [개발 진행](docs/개발진행.md)에 연결했다.

```bash
node scripts/verify-design.mjs --static
node scripts/verify-design.mjs
```

설계 웹 검사는 Chromium·Firefox의 1280·1440 너비에서 탐색·키보드·직접 경로·새로고침·가로 넘침을 확인한다. 제품 서버·SSO·DB의 합격을 뜻하지 않는다.

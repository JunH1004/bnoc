## 2026-10-14 · 완성도 고도화 분석과 개선안 제안

이전 제안은 위 PC 전용 구현 승인으로 대체됐다. 모바일 관련 후보와 기준은 이 절에서도 제거했다. 원래 제안과 당시 실행 증거는 Git 이력에 보존한다. 아래 분석 시점의 미실행 상태와 현재 결과를 구별한다.

**사용자 결정:** “기능이 다 있는거랑 완성도는 다른거야 완성도 고도화 방안을 중간 목표로 추가할게”. 순서는 기본 구현·안정화, 완성도 고도화, 설문·실무 의견 기반 추가 기능, 발표 준비다. 중간 목표 삽입은 확정이다. 아래 개선안·결과 기준은 **AI 제안이며 제품 개편 승인은 아니다**. 새 기능 개발이나 업무 변경으로 확대하지 않는다.

### 현재 분석과 증거의 범위

현재 제품 기준은 `44fdb8c`다. 업무 흐름·권한·DB/첨부·중복/충돌·재시작 보존에는 기존 실행 증거가 있다. 기능 존재·자동 검사 통과만으로 화면 편의성과 현업 적합성이 입증되지는 않는다. 이번에는 원래 명세·실제 소스·기존 PNG/검증 JSON을 읽었으며 새 브라우저 실행·업무 입력·제품 테스트는 수행하지 않았다. 임의의 완성도 점수나 개선율은 산정하지 않았다.

- **소스에서 확인한 불일치:** 요청 입력은 빈 세부 유형도 `subcategories`에 보낸다. 서버가 그룹 오류 `fieldErrors.subcategories`를 반환하는데 화면은 개별 선택칸 키만 표시한다. 따라서 해당 선택칸의 오류 표시·첫 오류 초점 연결이 빠지는 구조다. 서버 필수값 검사는 존재한다. [입력 변환](../frontend/src/api/requestPayload.mjs)·[서버 검사](../backend/src/main/kotlin/bnoc/WorkflowService.kt)·[입력 화면](../frontend/src/screens/RequestRegistrationForm.tsx). 실제 화면 재현은 아직 하지 않았다.
- **화면 배치 분석:** 공유 현황은 필터·집계·부서 카드 뒤에 선택 목록을 둔다. 현재 소스에서 확인한 배치 문제이며, 기존 화면의 구현 구분 배지는 이미 제거된 이력이다.
- **소스·이전 화면에서 확인한 안내:** 요청 상세의 여러 처리 성공 안내가 “처리했습니다.”로 같고, 작업 화면의 성공 안내는 새 편집 후에도 남을 수 있다. 병력/야간 성공 안내는 모든 부서 카드 아래에 있다. [요청 상세](../frontend/src/screens/RequestDetailWorkspace.tsx)·[작업 입력](../frontend/src/screens/WorkExecutionPanel.tsx)·[병력/야간](../frontend/src/screens/PersonnelViews.tsx). 이 배치로 실제 사람이 오해한 횟수는 측정하지 않았다.
- **조회 맥락:** 신청 목록·BNOC 현황은 실패 때 이전 결과를 보존하지만 그 결과의 적용 조건·성공 시각을 함께 표시하지 않는다. 공유 현황은 마지막 조회 안내가 있으나 보존된 결과의 조건 구분까지 대조해야 한다. 요청/작업 집계 단위, 요청/지원 유형, 대리 등록/새 작업 신청 등의 표현도 더 명확하게 연결할 여지가 있다. BNOC 현황의 전용 PNG는 이번에 찾지 못했으며 소스 분석으로 구별한다.
- **미검증:** 현업의 찾기 시간·도움 요청·입력 실수, 전체 접근성, 누적 자료의 응답 시간·동시 사용 성능, 다른 물리 PC의 반복 시연. 긴 시험 목록이나 달력 PNG를 실제 운영량·부하 결함의 증거로 쓰지 않는다. 최신 로그인/인증 화면은 단일 행동이 명확해 우선 재설계 대상에서 제외하는 제안이다.

### 유지할 업무와 설계 경계

신청 검색은 버튼·Enter, 초기화는 한 번 조회다. **BNOC 현황 빠른 필터는 즉시 적용**한다. 필터를 접는 제안은 이 동작을 통일하자는 뜻이 아니다. 기존 필수/조건부/선택 입력, 희망 일정과 작업 일정의 구별, BNOC 분류·부서 배정과 작업반 일정/담당 인원 책임, 명시적 저장·서버 커밋 뒤 성공 표시, 충돌 때 입력 보존·명시적 교체, 공유 필드/상세/수정 권한과 현재 집계 산식을 유지한다. 자동 저장·우선순위 자동 정렬·새 승인 절차·공유 상세 확대를 추가하지 않는다. 임시 단계·가짜 이름/계급·화면의 모의/대회용 설명도 추가하지 않는다.

적용 대상은 기존 신청/입력·이력/알림·목록/달력·현황·운영 화면과 공통 조회/저장 상태다. 현재 기능 명세와 모듈 배정은 그대로다. 후보를 검토한 뒤 관련 유스케이스, 시스템 요구사항, 기존 아키텍처 웹, 개발 명세에 필요한 개정을 연결하고 구현한다. 여기의 UI 후보를 구현 승인이나 새 필수 업무로 승격하지 않는다. 연결부 교체·인터넷 없는 설치·백업/복원·업데이트·운영 인수의 이식 고도화 유예도 유지한다.

### 중간 목표를 닫는 기준 — 제안

대표 과제는 여섯 묶음으로 제안한다: 요청 등록/조회, BNOC 분류·복수 부서 배정과 집계 구별, 작업반 일정·상태 처리, 반환 재배정/완료 후보고, 부서별 병력·야간 현황, 공지·첨부. 검수자는 실제 또는 예상 사용자다. 먼저 업무 담당자의 검수로 부대 업무와 다른 점을 확인하며 다른 역할 사용자 검수 여부도 따로 기록한다. 실명·실제 운영 자료를 공개 시연이나 증거로 넣지 않는다.

1. **막힘 없음:** 해당 역할의 대표 과제를 화면 동작 설명 없이 끝낸다. 완료 여부·도움 요청·잘못 선택한 부서/날짜/집계 단위·되돌아간 화면·시간을 기록한다. 업무 자체를 처음 배우는 시간과 UI 설명 도움을 구별한다. 여러 역할 사용자를 확보하기 전에는 한 사람 검수를 전체 사용자 적합성으로 일반화하지 않는다.
2. **같은 조건으로 비교:** 개선 전후 같은 역할·과제·자료 조건에서 측정한다. 아직 기준판의 시간이 없으므로 ‘몇 % 빨라짐’을 정하지 않는다. 전후 시간이 나아졌는지와 새 혼동이 생기지 않았는지를 함께 확인하고 반복 학습 효과도 기록한다. 측정 뒤 필요하면 수치 목표를 따로 검토한다.
3. **표현과 접근:** PC1280/1440에서 핵심 과제 수행·현재 위치·첫 오류 초점을 확인한다. 문자 대비는 일반 글자 4.5:1, 큰 글자 3:1을 적용하고 클릭 영역은 WCAG 2.2의 24×24 CSS px 또는 해당 예외 조건을 확인하는 안이다. 이 일부 항목 확인만으로 전체 WCAG 준수를 주장하지 않는다.
4. **기존 기능 퇴행 없음:** 신청·배정·일정·상태·반환·후보고·권한·첨부·중복/충돌·입력 보존의 관련 기존 검사 통과. 오류 안내·조회 실패·재편집 같은 바뀐 조건은 실패 화면을 먼저 재현하고 수정 뒤 확인한다. 화면 배치/문구만 바꾸면 새 업무 오류 주입을 만들지 않으며, 권한·필수 입력 검사를 바꾸면 기존 감도 절차를 적용한다.

이 과제 수행 방식은 [GOV.UK 사용자 과제 검수 안내](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing)의 목표 중심·답을 미리 알려주지 않는 방식에서 참고했다. 대비·클릭 영역 수치는 [W3C 문자 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)·[W3C 클릭 영역](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)을 확인했다. 대회의 공식 합격 기준이 아니라 이번 프로젝트의 완성도 측정 제안이다.

문서 제안의 독립 검토·경로/근거 대조 결과는 검토 (비공개 출처: `../runtime/evidence/backend-implementation-20261013/completeness-analysis-20261014/reviewer.json`)·검증 (비공개 출처: `../runtime/evidence/backend-implementation-20261013/completeness-analysis-20261014/verifier.json`)에 기록한다. 개선 구현·현업 과제 측정·접근성/성능/다른 PC 검수는 아직 미실행이다.

## 2026-10-14 · 사용자 화면의 구현 설명 제거

- 사용자 지적에 따라 로그인 안내·상단 배지·인증 창·상황의 모의/대회용 문구와 CPCON 구현 설명을 제거했다. GPS 정보원·CPCON 정보원, 단계·시각·수집 실패 안내는 유지했다. 업무 규칙·인증 검증·내부 sourceMode는 변경하지 않았다. 핵심 명세·기존 설계 웹·AGENTS를 먼저 맞췄다.
- 기존 E2E의 표시 기대값 두 곳만 최신 사용자 결정으로 정정하고 독립 검토를 받았다. 인증·출처 검증·단계/시각/실패 조건은 유지했다. 표시 변경 diff (비공개 출처: `../runtime/evidence/backend-implementation-20261013/ui-text-20261014/ui-wording.patch`)·검토 (비공개 출처: `../runtime/evidence/backend-implementation-20261013/ui-text-20261014/reviewer.json`). 새 업무 기준·새 문서 종류·오류 주입 실험은 만들지 않았다.
- 검증: 화면 단위 48/48·제공자 3/3·서버 35/35·화면/서버 빌드, 설계 정적/6브라우저 조합 통과. 전용 8083의 기존 로그인·상황 두 흐름은 Chromium/Firefox와 390/1280/1440에서 12/12 통과했다. 8083은 종료했다. 이번에 전체 HTTP·전체 UI·저장/감도 검사를 다시 실행한 것으로 기록하지 않는다.

## 2026-10-14 · 공개 HTTPS 접속 제공

- 출처·범위: 사용자 “장난하니? 로컬?”에 따라 로컬 주소 전달을 정정한다. 업무 계약 변경 없이 다른 컴퓨터에서 로그인·실제 API 저장·첨부를 사용할 수 있는 HTTPS 주소를 제공한다. 기존 공개 정적 데모를 새 백엔드 결과로 사용하지 않는다. 읽기 전용 spec_mapper가 공개 인증 URL과 서버 검증 주소를 혼용한 결함을 확인했다.
- 환경: 현재 연결된 Sites는 정적/Worker 호스팅이며 승인된 JVM·MySQL 서버를 실행할 수 없다. 별도 상시 호스팅 계정은 확인하지 못했다. Railway 설치·연결을 제안했으나 연결은 미확인이다. 우선 공식 Cloudflare HTTPS 터널과 별도 빈 대회 DB·첨부·모의 제공자를 사용한다. 컴퓨터 실행 의존·임시 주소를 상시 배포로 표현하지 않는다.

## 검사가 좋아졌는데 실험이 실패하는 문제

- 종류·버전: 검증 도구 결함. `5863eca`의 실행기는 오류 복사본에서도 기존 시험이 반드시 통과해야 한다고 요구했다.
- 근거: 정상은 통과하고 잘못된 동작은 거부해야 한다. 기존 회귀 검사가 같은 오류를 잡기 시작하는 것은 검사 능력의 개선이다. 기존 시험 결과는 관찰값이며, 합격 조건은 정상 통과와 원문 근거 검사의 의도한 오류 탐지다.
- 재현: 임시 복사본의 기존 시험에 일정 자동 입력 금지 검사를 추가했다. 해당 검사는 오류를 잡았으나 실행기가 `mutated: existing tests did not pass`로 실패했다.
- 변경: 오류 복사본의 기존 시험은 통과/실패를 관찰하고, 실패 이유를 검토 대상으로 남긴다. 정상 시험 실패, 계약 검사의 잘못된 결과, 문법·모듈 오류는 여전히 성공으로 처리하지 않는다.
- 회귀 검사: `node --test experiments/ai-workflow/run-sensitivity.test.mjs`. 실행기·집계·합격 판정 변경 때 실행한다. 정상, 개선된 기존 검사, 깨진 정상 기준 세 조건을 확인한다.
- 실제 결과: 수정 전 2통과/1실패로 의도한 문제를 재현, 수정 후 3/3 통과. 첫 테스트 작성 시 Node 하위 시험 프로토콜이 상속돼 3개가 다른 이유로 실패한 실행은 결함 재현으로 세지 않았다. 테스트 실행 환경을 분리한 뒤 의도한 실패를 확인했다.
- 검증 중 보완: 스킬이 요구한 주입 diff를 실행기가 파일로 남기지 않던 누락을 발견했다. diff 저장 확인 시험을 추가해 실패를 확인한 뒤 실제 변경 행을 `mutation.patch`에 저장하도록 수정했다. 최종 독립 회귀 시험 3/3, 로그 (비공개 출처: `../runtime/evidence/workflow-apply-20261013/runner-tests.log`). 실행기 변경 때 이 보존 조건도 재검사한다.
- 한계: 기존 시험의 새 실패는 `failed-needs-review`로 남긴다. 임의의 실패를 업무 오류 탐지 성공이라고 자동 판정하지 않는다.

- 종류·버전: `fed2b10` 이후 `scripts/verify-design.mjs` 개정. 경계·분류의 인공 오류 검사이며, 증거 누락은 검증 도구의 실제 결함이다.
- 기대: 정상 설계는 통과하고 서버 업무의 브라우저 이동, BNOC 필수 분류의 선택화는 각각 거절한다. 주입한 변경 행·실행기 버전·원본 불변·임시 복사본 정리를 추적할 수 있어야 한다.
- 실제: 처음 새 검사는 과거 HTML에 없는 `DOMAINS`를 읽어 실패했다. 이를 오류 탐지로 세지 않고 수정한 뒤 의도한 `BACKEND_BOUNDARY_REQUIRED` 실패를 확인했다. 후속 verifier가 실제 주입 diff·검사기 해시 누락을 찾았다. 이전 일정 실험에서 지적된 증거 보존 누락이 새 실행기에도 재발한 사례다.
- 수정·재현: `node scripts/verify-design.mjs --fault-check`. 두 복사본 모두 의도한 assertion에서 거절됐고 각 실제 diff, 원본/변형본/검사기 SHA256, 임시 파일 정리 결과를 저장했다. 최종 증거 (비공개 출처: `../runtime/evidence/backend-architecture-design-20261013/fault-check.json`). 다음 설계 검사·오류 주입 실행기 변경에도 저장된 실제 diff와 버전을 직접 확인한다.
- 기존 실패 재사용: 작업 일정 실험도 다시 실행해 정상 27/27·3/3, 오류 복사본 27/27·2통과/1의도한 실패를 재현했다. 결과 (비공개 출처: `../runtime/evidence/backend-architecture-design-20261013/sensitivity/summary.json`)·diff (비공개 출처: `../runtime/evidence/backend-architecture-design-20261013/sensitivity/mutation.patch`). 실제 서버 권한, 전체 오류 예방률을 입증하는 결과는 아니다.

## CPCON 누락과 모의 연동 계약 누락

- 종류·버전: `42a737e`의 설계 누락. 사용자가 CPCON 부재와 실제 SSO·GPS 연결 불가 조건을 지적했다. 당시 요구사항에 CPCON을 예시/선정 대기로 남겼지만 기능 명세·모듈에는 없었다. 제품 결함이나 AI 선제 발견이 아니다.
- 기대·정정: 공고 R02의 CPCON을 독립 기능으로 추적하고 모의 인증/상황 제공자와 실제 BNOC 세션·권한·수집·저장을 연결한다. CPCON 단계·적용 범위를 GPS에서 복사하지 않으며 실제 연동 미확정을 대회 설계 중단 조건으로 쓰지 않는다. 기존 핵심 문서·웹에 반영했다.
- 재검사: `node scripts/verify-design.mjs --static`, `--fault-check`, 브라우저 실행. 새 기능 추가·공고 대응·외부 제공자·인증 경계 변경 시 공고 항목과 실제 기능/모듈 연결을 함께 대조한다. 단순 명칭의 존재만으로 공고 충족을 판단하지 않는다.
- 실제 결과: 기존 HTML에서 `CPCON_FUNCTION_REQUIRED` 실패, 개정본 정상 통과. CPCON 삭제 복사본과 운영 모의 인증 허용 복사본은 지정 assertion에서 실패했고 기존 서버 경계/분류 오류도 재검사했다. 4건 주입 diff·해시·정리 (비공개 출처: `../runtime/evidence/external-integration-design-20261013/fault-check.json`).
- 독립 검토 발견: 로그인 요청이 시작 브라우저와 결합되지 않은 조건, 첫 수집 실패를 미수집으로 표시한 조건, 인증 시작/완료 API의 모듈 연결 누락을 수정했다. 다음 인증·수집 계약 변경 시 이 조건을 재대조하고 구현 단계에는 다른 브라우저의 유효 확인표 제출·첫 수집 실패를 실제 서버 시험으로 확인한다. 현재는 설명 검사다.
- 마지막 상태: 두 브라우저·세 너비 통과, 독립 재검토 잔여 지적 없음. 실행 범위 (비공개 출처: `../runtime/evidence/external-integration-design-20261013/verification.json`)·검토 (비공개 출처: `../runtime/evidence/external-integration-design-20261013/review.json`)·검증 (비공개 출처: `../runtime/evidence/external-integration-design-20261013/verifier.json`). 실제 공군 호환·제품 기능·최종 공고 충족·사용자 승인은 미검증이다.

## 효과 측정

이번에는 절차 연결과 재검사 가능 여부를 확인한다. 과거 일정 실험 재현과 도구 결함 수정은 관찰된 결과다. 전체 AI 오류 감소율·개발 생산성은 아직 미측정이다. 다음 관련 작업에서 사례별 재발, 실제 사람 수정, 확인된 시간·사용량을 누적하되 AI 리뷰 수정과 사람 수정을 섞지 않는다. 비교 계획은 [AI 개발 방식 비교와 도입안](AI개발방식_비교와도입안.md)을 따른다.
